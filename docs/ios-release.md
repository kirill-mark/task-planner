## Сделано

- Создан проект Xcode на Capacitor 8.5.2 с Swift Package Manager.
- Зафиксированы версии зависимостей в package-lock.json.
- Интерфейс и Supabase SDK включены в приложение: при запуске не нужно скачивать JavaScript с CDN.
- Сохранён отдельный веб-вход для PWA/Telegram. В сборке iOS не подключаются Telegram WebApp SDK и service worker.
- Подготовлены иконка MARK 1024×1024 без альфа-канала и экран запуска с логотипом.
- Добавлен PrivacyInfo.xcprivacy: имя, email, идентификатор аккаунта и пользовательское содержимое для работы приложения. Перед отправкой нужно сверить декларацию с окончательным составом функций и облачной конфигурацией.
- Сервер помощника проверяет сохранённое согласие до чтения задач и обращения к Groq; при ошибке чтения согласия запрос блокируется.
- Резервное копирование блокируется и при отсутствующем, и при неверном секрете расписания.
- Подготовлено восстановление забытого пароля в обоих интерфейсах: письмо, отдельная страница recover.html, новый пароль в браузере и возврат в MARK вручную. Код ещё не опубликован и не проверен с настоящим письмом.
- Экспорт JSON/CSV в iOS использует официальный Filesystem 8.1.4 и Share 8.0.3: временный файл в кеше приложения и системное меню «Поделиться». Веб-версия использует скачивание. Добавлена декларация FileTimestamp/C617.1 для Filesystem.

## Как открыть

Открыть `ios/App/App.xcodeproj` в Xcode. Скопированные ресурсы и исходники трёх нативных плагинов уже включены, поэтому для первого открытия не требуется запускать npm. В поставке находятся три пакета в node_modules/@capacitor (filesystem, local-notifications и share); для npm-команд всё равно нужен npm ci. Xcode загрузит официальные Swift-пакеты Capacitor и IONFilesystemLib, если их ещё нет в кеше; версии зафиксированы в Package.resolved.

Для запуска в симуляторе выбрать конкретный iPhone в верхней панели и нажать Run. 5 октября обнаружена ошибка загрузки iOS 27.0 Simulator: сервер Apple отклонил запрос. Повторная установка отображала Preparing…; альтернативный официальный iOS 26.5 был поставлен в очередь, но установленный симулятор не появился. Запуск на виртуальном iPhone не подтверждён.

Для запуска на физическом iPhone понадобятся выбранная команда в Signing & Capabilities и подпись. Для TestFlight потребуется активный Apple Developer Program.

6 октября подключён iPhone KIRILL MARK (iOS 26.6.2). Кирилл вошёл в Apple Account, выбрана Personal Team; Xcode показал профиль и сертификат, подпись настроена в обеих копиях проекта. Кирилл включил Developer Mode. Xcode подготовил системные символы устройства и дошёл до запуска MARK, но остановился на «Developer App Certificate is not trusted». Кирилл подтвердил доверие к сертификату. Следующий Run успешно запустил процесс MARK на iPhone и загрузил WebView. По сообщению Кирилла, вход и сохранение тестовой задачи после закрытия прошли. В веб-версии Chrome агент увидел созданную на iPhone задачу «Тест IOS 6 октября»: облачная синхронизация подтверждена. Проверяем офлайн-переименование с последующим возвратом связи; текущий чек-лист — MARK-iPhone-test.md рядом с поставкой.

## Как обновлять ресурсы

```sh
npm ci
npm run ios:sync
npm test
```

`npm run ios:sync` пересобирает интерфейс и копирует его в проект Xcode. Повторно открыть проект можно через `npm run ios:open`.
