# Предложения помощника: контракт применения (пакет A, ТЗ v1.1)

Пункты AI01–AI03 и A2–A5. Код: `js/mark/localdb.js`, `js/mark/engine.js`
(`applyProposal`, `proposalStatus`), `js/mark/store.js`, `applyProposal` в
`js/ui/app.js`, карточка в `js/ui/views.js`. Тесты: `tests/engine-smoke.js`,
блок «предложения помощника».

## Идентификаторы

Выдаются **в момент показа черновика** и сразу сохраняются в чате:

| Поле | Где | Назначение |
| --- | --- | --- |
| `proposal_id` | сообщение помощника | одно предложение; повтор применения с тем же ID ничего не пишет |
| `action_id` | каждое действие | связь действия с его итогом |
| `operation_id` | каждое действие | ключ повтора на сервере (`mark_apply_operations` узнаёт повтор) |
| `id` объекта | каждое действие | для новой задачи — ID, выданный сервером помощника |

Чаты, сохранённые до этой версии, получают ID при первом нажатии «Применить»
— и сначала они записываются в чат, потом операции в очередь.

## Применение

1. Повторное нажатие блокируется на время сохранения.
2. Предложение и все выбранные операции записываются в IndexedDB **одной
   транзакцией** (`appendProposal`): либо весь набор с записью о нём, либо
   ничего. Отказ хранилища — ошибка, черновик остаётся, повтор возможен.
3. Предложение с уже записанным `proposal_id` не пишется снова — возвращается
   прежняя запись (двойное нажатие, перезапуск).
4. «Применить» завершается только после записи; дальше статус — по операциям.

## Статусы

Действие: `queued` (ждёт отправки, нет сети) → `syncing` (отправляется) →
`applied` (сервер принял) | `conflict` (версия устарела, объект удалён) |
`failed` (сервер отказал) | `cancelled` (пользователь отказался от правки при
конфликте).

Итог действия записывается в запись предложения **в той же транзакции**, что
и состояние операции в очереди, поэтому он сохраняется после того, как
применённая операция уходит из очереди при сверке.

Предложение целиком: `applied` — только если сервер принял все выбранные
действия; иначе показывается «Применено N из M» и причина у конкретной задачи.

В интерфейсе: «Сохраняю…» (запись на устройстве), «Сохранено на устройстве —
отправится, когда появится связь», «Сохранено на устройстве, отправляется…»,
«Применено», «Применено 1 из 2. Задачу успели изменить в другом месте…».

## Хранение

Записи о предложениях — в базе устройства конкретного аккаунта (`mark:<user>`),
другой аккаунт их не видит. Завершённые старше 90 дней удаляются при открытии;
повтор такого старого предложения копий не создаст — сервер узнаёт операции
по `operation_id`.

## Что не входит в пакет A

Атомарное применение связанного плана (PL03), отмена принятого (PL04), срок
актуальности предложения (`expires_at`) — этапы C–D. Telegram-бот работает
по-прежнему через свои черновики и подтверждения.
