# Работа над MARK: Codex и Claude в одном репозитории

Над проектом работают два инструмента — Codex и Claude Code — в разных папках
на одном компьютере. Общая точка — GitHub: `kirill-mark/task-planner`.
Эти правила обязательны для обоих.

## Ветки

- **`codex/ios-release`** — рабочая ветка. Вся текущая работа идёт здесь.
- **`main`** — опубликованная веб-версия: GitHub Pages выкладывает её сразу
  после отправки. В `main` вливать только осознанно, когда веб-версия
  проверена, и с поднятым `CACHE_NAME` в `sw.js`.

## Перед началом работы

```bash
git status            # должно быть чисто; если нет — сначала разобраться
git pull --rebase     # забрать то, что сделал другой инструмент
```

## После работы — каждый раз, не оставляя на потом

```bash
git add <изменённые файлы>
git commit -m "что сделано и зачем"
git push
```

Незакоммиченная работа в конце сессии недопустима: другой инструмент её не
увидит, а при потере папки её не восстановить.

## Сервер Supabase

Функции и миграции выкладывать **только из закоммиченного и отправленного
кода, после `git pull`**. Иначе можно откатить то, что выложил другой
инструмент (так уже было бы с помощником: на сервере стоит версия из Codex от
10 октября, которой не было в основной папке).

После выкладки — строка в `docs/deploys.md`: дата, что выложено, коммит.

Не применено и ждёт решения владельца: миграция `0014_mark_empty_trash.sql`.
